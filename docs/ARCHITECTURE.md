# معماری یادینو

## نمای کلی

یادینو یک برنامه اندرویدی تک‌Activity با رابط Jetpack Compose است که بر اساس **MVVM** و اصول **Clean Architecture** لایه‌بندی شده است. منطق مهم (تقویم، تکرار، عادت‌ها، پیشرفت اهداف، گزارش‌ها، قالب پشتیبان و اعتبارسنجی) در ماژول‌های Kotlin خالص قرار دارد تا مستقل از اندروید آزمون‌پذیر باشد.

```
┌──────────────────────────────── app (Android) ────────────────────────────────┐
│  UI (Compose + Material 3)   ViewModel ها   ابزارک‌ها (RemoteViews)   اعلان‌ها │
│            │                      │                │                    │      │
│            └──────────── Repository ها (TaskRepository, NoteRepository …) ─┘     │
│                          │                         │                           │
│                Room (SQLite)               DataStore (تنظیمات)                 │
│                          │                                                      │
│      DataSideEffects → زمان‌بندی یادآورها (AlarmManager) + به‌روزرسانی ابزارک‌ها │
└────────────────────────────────────┬───────────────────────────────────────────┘
                                     │ وابستگی
                    ┌────────────────▼──────────────┐
                    │ core:domain (Kotlin/JVM)       │ مدل‌ها، تکرار، عادت، هدف، گزارش،
                    │                                │ پشتیبان/بازیابی، تنظیمات، اعتبارسنجی
                    └────────────────┬──────────────┘
                    ┌────────────────▼──────────────┐
                    │ core:calendar (Kotlin/JVM)     │ تقویم جلالی، قالب‌بندی، مناسبت‌ها
                    └───────────────────────────────┘
```

## ماژول‌ها

### `core:calendar`
- `JalaliCalendar`: محاسبات پایه بر اساس جدول سال‌های «شکست» چرخه ۳۳ ساله (Borkowski)، معتبر برای سال‌های ۱ تا ۳۱۷۷. همه تبدیل‌ها از طریق **روز اپوک ISO** انجام می‌شوند.
- `JalaliDate`: نوع تغییرناپذیر تاریخ با جمع روز/ماه/سال (ماه و سال با برش به آخر ماه: ۳۱ شهریور + ۱ ماه = ۳۰ مهر).
- `CalendarFormatter`, `TimeFormatter`, `Digits`: قالب‌بندی الگومحور (`EEEE d MMMM yyyy`)، ساعت ۱۲/۲۴ با «ق.ظ/ب.ظ»، اعداد فارسی/لاتین.
- `WeekMath`: شبکه ۶×۷ ماه، شروع و پایان هفته، شماره هفته در سال شمسی با روز شروع قابل تنظیم.
- `HijriCalendar` و `IranianOccasions`: تعطیلات و مناسبت‌های شمسی (دقیق) و قمری (تقویم قمری محاسباتی؛ با برچسب «تقریبی» و اصلاح کاربر).

## قواعد ذخیره‌سازی (بدون ابهام)

| نوع داده | شکل ذخیره در پایگاه داده | شکل در پشتیبان |
|---|---|---|
| تاریخ تقویمی | روز اپوک ISO (`INTEGER`) | `2026-10-14` |
| ساعت دیواری | دقیقه از نیمه‌شب (`INTEGER` ۰..۱۴۳۹) | `09:30` |
| لحظه زمانی | میلی‌ثانیه UTC (`INTEGER`) | ISO-8601 UTC |
| شمارشی‌ها | نام ثابت (`TEXT`) | نام ثابت |
| شناسه‌ها | UUID تصادفی (`TEXT`) | UUID |

تاریخ و ساعت کارها «شناور» (محلی) هستند: کاری که برای ساعت ۱۰ برنامه‌ریزی شده با تغییر منطقه زمانی یا ساعت تابستانی همان ساعت ۱۰ محلی می‌ماند و فقط زمان هشدار دوباره محاسبه می‌شود. نمایش جلالی فقط در لایه نمایش تولید می‌شود.

### طرح‌واره پایگاه داده (نسخه ۲)

| جدول | کلید خارجی | توضیح |
|---|---|---|
| `categories` | — | دسته‌ها (پیش‌فرض و دلخواه) |
| `goals` | `category_id → categories (SET NULL)` | اهداف |
| `notes` | `category_id`, `goal_id` (SET NULL) | یادداشت‌ها |
| `tasks` | `category_id`, `goal_id`, `source_note_id` (SET NULL) | کار/رویداد/یادآور؛ ایندکس روی تاریخ، مهلت، وضعیت |
| `subtasks` | `task_id → tasks (CASCADE)` | زیرکارها |
| `task_completions` | `task_id → tasks (CASCADE)` | تاریخچه انجام نوبت‌ها (برای تکرار و گزارش) |
| `milestones` | `goal_id → goals (CASCADE)` | مراحل هدف |
| `habits` | `goal_id → goals (SET NULL)` | عادت‌ها |
| `habit_logs` | `habit_id → habits (CASCADE)`؛ یکتا `(habit_id, date)` | ثبت انجام روزانه |
| `note_drafts` | — | پیش‌نویس ذخیره‌نشده ویرایشگر (بازیابی پس از بسته شدن ناگهانی) |
| `deletions` | — | سنگ‌قبر حذف‌ها برای همگام‌سازی آینده |
| `plan_templates` | — | قالب‌های برنامه (از نسخه ۲): نام، توضیح، بازه (`span_days`: ۱ یا ۷) |
| `template_items` | `template_id → plan_templates (CASCADE)`، `category_id`، `goal_id` (SET NULL) | موارد قالب: روز (`day_offset`)، ساعت‌ها (دقیقه از نیمه‌شب)، مهلت نسبی (`due_offset`)، یادآوری، زیرکارها و برچسب‌ها |

طرح‌واره کامل هر نسخه در `app/schemas/ir.yadino.app.data.local.YadinoDatabase/` است (`1.json` و `2.json`).

**مهاجرت ۱ → ۲ (یادینو ۱٫۳)**: فقط دو جدول تازه و ایندکس‌هایشان ساخته می‌شوند و جدول‌های موجود دست نمی‌خورند. SQL مهاجرت در `MigrationSql` بدون وابستگی به اندروید نوشته شده است تا `DatabaseMigrationTest` بتواند آن را روی SQLite واقعی اجرا کند: پایگاه داده‌ای از طرح‌واره نسخه ۱ با داده نمونه ساخته، مهاجرت اجرا و نتیجه با پایگاه داده ساخته‌شده از طرح‌واره نسخه ۲ مقایسه می‌شود. روی دستگاه، `MigrationTest` همین مسیر را با اعتبارسنجی خود Room هم بررسی می‌کند. حالت حذف و ساخت دوباره فعال نیست.

## جریان‌های اصلی

### انجام کار تکرارشونده
`TaskRepository.setCompleted` ← `TaskCompletionLogic.complete`:
1. یک رکورد در `task_completions` با تاریخ نوبت ثبت می‌شود.
2. نوبت بعدی با `RecurrenceEngine` از روی «لنگر سری» (`recurrenceStart`) محاسبه می‌شود تا روز ماه حفظ شود (۳۱ → ۳۰ → … → ۳۱).
3. بسته به تنظیم «انجام کار تکرارشونده»: کار به نوبت بعد منتقل می‌شود، یا یک نسخه انجام‌شده هم نگه داشته می‌شود. زیرکارها برای نوبت بعد بازنشانی می‌شوند. با پایان سری، کار «انجام‌شده» می‌شود.
4. برگرداندن تیک، آخرین رکورد انجام را حذف می‌کند.

### یادآورها
- `ReminderCalculator` (دامنه) زمان دقیق را با منطقه زمانی و ساعات سکوت محاسبه می‌کند.
- `ReminderScheduler` با `setExactAndAllowWhileIdle` (در صورت داشتن مجوز «هشدارهای دقیق») یا `setAndAllowWhileIdle` هشدار می‌گذارد.
- پس از هر تغییر داده، `DataSideEffects` هشدارهای مربوط را به‌روز یا لغو می‌کند.
- پس از راه‌اندازی مجدد، به‌روزرسانی برنامه، تغییر ساعت/منطقه زمانی، تغییر مجوز هشدار دقیق و تغییر تنظیمات اعلان، همه هشدارها از نو ساخته می‌شوند.
- اعلان‌ها دکمه «انجام شد» و «یادآوری دوباره» دارند؛ یادآوری بی‌پاسخ طبق تنظیم تکرار می‌شود.

### ابزارک‌ها
- بدون سرویس دائمی و با `updatePeriodMillis=0`؛ به‌روزرسانی رویدادمحور: تغییر داده (با تأخیر ۴۰۰ میلی‌ثانیه برای تجمیع)، تغییر تنظیمات مؤثر، هشدار کم‌مصرف نیمه‌شب و رویدادهای سیستم.
- رندر در پس‌زمینه با `goAsync`؛ فهرست‌ها با `RemoteViewsService`.
- اندازه (کوچک/متوسط/بزرگ) از ابعاد فعلی ابزارک تعیین می‌شود؛ هر نمونه تنظیمات مستقل در DataStore دارد.
- تیک زدن کار یا ثبت انجام عادت از روی ابزارک، از طریق یک Activity نامرئی (trampoline) مستقیماً در پایگاه داده ذخیره می‌شود و همه ابزارک‌ها به‌روز می‌شوند. ثبت عادت همان قاعده داشبورد را دارد (`HabitRepository.checkIn`).
- ابزارک یادداشت سریع (از نسخه ۱٫۳) در اندازه متوسط و بزرگ، یادداشت فهرست‌دار را به‌صورت فهرست (`NoteChecklistWidgetService`) نشان می‌دهد. لمس هر مورد، شماره، متن و وضعیت نمایش‌داده‌شده آن را به Activity نامرئی می‌فرستد. `Checklist.toggleShown` مورد را دوباره پیدا می‌کند، حتی اگر یادداشت در این فاصله ویرایش شده باشد (اول با همان شماره و متن، وگرنه نخستین مورد با همان متن و همان وضعیت). اگر وضعیت مورد دیگر با آنچه ابزارک نشان داده یکی نباشد (لمس دوباره پیش از تازه شدن فهرست)، چیزی تغییر نمی‌کند و فقط ابزارک تازه می‌شود.
- ابزارک شمارش معکوس، انتخاب کاربر را به‌صورت `goal:<id>`، `task:<id>` یا خالی (نزدیک‌ترین موعد) در `WidgetConfig.content` نگه می‌دارد. اگر مورد انتخابی حذف یا بایگانی شود، ابزارک این را نشان می‌دهد و لمس آن صفحه تنظیم همان نمونه را باز می‌کند.
- ساعت با `TextClock` نمایش داده می‌شود (بدون بیدار کردن برنامه در هر دقیقه).

### پشتیبان‌گیری و بازیابی
```
خواندن فایل/درایو → BackupCodec.decode (قالب، نسخه، SHA-256، ساختار)
→ BackupValidator (شناسه یکتا، ارجاعات) → RestorePlanner (جایگزینی | ادغام)
→ پیش‌نمایش و تأیید کاربر → نسخه ایمنی از داده فعلی
→ DataRepository.replaceAll در یک تراکنش → زمان‌بندی دوباره یادآورها و ابزارک‌ها
```
- **ادغام**: رکوردها بر اساس شناسه یکی می‌شوند و نسخه‌ای که `updatedAt` جدیدتری دارد می‌ماند؛ ثبت عادت‌ها بر اساس (عادت، روز) ادغام می‌شوند؛ تنظیمات فعلی حفظ می‌شود.
- **جلوگیری از بازیابی ناقص**: هر خطا در میانه تراکنش همه تغییرات را برمی‌گرداند.
- **جلوگیری از بازیابی تکراری**: کد اعتبارسنجی آخرین پشتیبان بازیابی‌شده نگه داشته و هشدار داده می‌شود.
- **نسخه‌های قالب پشتیبان** (`yadino-backup`):
  - نسخه ۱ (یادینو ۱٫۰ تا ۱٫۲): کارها، یادداشت‌ها، اهداف، عادت‌ها، دسته‌ها و تنظیمات اصلی.
  - نسخه ۲ (از یادینو ۱٫۳): بخش‌های `templates` و `templateItems` هم اضافه شده‌اند.
  - فایل‌های قدیمی‌تر همان‌طور خوانده می‌شوند و بخش‌های جاافتاده‌شان خالی در نظر گرفته می‌شود. «جایگزینی کامل» با فایل نسخه ۱ قالب‌های فعلی را نگه می‌دارد (`RestorePlanner.keepsLocalTemplates`)، چون آن فایل درباره قالب‌ها چیزی نمی‌گوید.
  - فایل نسخه جدیدتر از نسخه برنامه رد می‌شود و هیچ بخشی از آن ناقص بازیابی نمی‌شود.

### پشتیبان رمزگذاری‌شده (از نسخه ۱٫۱)
اگر کاربر رمز پشتیبان تعیین کند، هر پشتیبان تازه (فایل، پوشه خودکار و گوگل‌درایو) پیش از ذخیره در یک «پاکت» رمزگذاری‌شده قرار می‌گیرد. این پاکت خودش JSON است:

```json
{ "format": "yadino-encrypted-backup", "formatVersion": 1, "appVersion": "1.1.0",
  "createdAt": "2026-10-14T08:00:00Z",
  "kdf": { "algorithm": "PBKDF2-HMAC-SHA256", "iterations": 600000, "salt": "<base64>",
           "passwordNormalization": "fa-v1" },
  "cipher": { "algorithm": "AES-256-GCM", "iv": "<base64>", "tagBits": 128 },
  "compression": "gzip",
  "payload": "<base64>" }
```

- **محتوا**: `payload` همان پشتیبان ساده (`yadino-backup`؛ نسخه ۲ از یادینو ۱٫۳) است که با gzip فشرده و با AES-256-GCM رمزگذاری شده است. پس از رمزگشایی، همه بررسی‌های معمول (SHA-256، ساختار، ارجاعات) دوباره انجام می‌شود. تعداد رکوردها و هر نوع محتوا فقط داخل `payload` است.
- **کلید**: کلید با PBKDF2-HMAC-SHA256 ساخته می‌شود؛ ۶۰۰٬۰۰۰ تکرار طبق توصیه OWASP ۲۰۲۳. برای هر فایل نمک ۱۶ بایتی و IV ۱۲ بایتی تازه انتخاب می‌شود. PBKDF2 روی بایت‌های صریح UTF-8 پیاده شده و با بردارهای RFC 7914 آزموده شده است؛ بنابراین نتیجه به ارائه‌دهنده رمزنگاری دستگاه وابسته نیست.
- **یکسان‌سازی رمز (`fa-v1`)**: رمز پیش از ساخت کلید یکسان‌سازی می‌شود تا با صفحه‌کلید فارسی، عربی یا انگلیسی یک کلید بدهد:
  - یکسان‌سازی یونیکد NFC.
  - «ي/ى» به «ی» و «ك» به «ک».
  - ارقام فارسی و عربی به ارقام لاتین.
- **احراز اصالت سرآیند**: همه مقادیر سرآیند به‌صورت داده همراه (AAD) در GCM احراز اصالت می‌شوند؛ تغییر هر کدام، مثلاً کم کردن تعداد تکرار، رمزگشایی را ناموفق می‌کند. فایل‌هایی که تعداد تکرارشان خارج از بازه ۱۰۰ هزار تا ۵ میلیون است، پیش از هر محاسبه رد می‌شوند. حجم داده پس از بازکردن فشرده‌سازی محدود است.
- **نگه‌داری رمز**: رمز در `SecureTokenStore` نگه‌داری می‌شود (AES-GCM با کلید Android Keystore؛ SharedPreferences در پشتیبان خودکار اندروید نیست)، تا پشتیبان‌های خودکار هم بدون پرسش رمزگذاری شوند.
  - یک پرچم غیرمحرمانه در `AppStateStore` روشن بودن رمزگذاری را به خاطر می‌سپارد.
  - اگر رمز روی دستگاه خوانا نباشد (مثلاً پس از انتقال به گوشی جدید)، حالت `UNAVAILABLE` است: پشتیبان‌گیری با پیام روشن متوقف می‌شود و **هرگز بی‌صدا فایل بدون رمز ساخته نمی‌شود**.
- **بازیابی**: `BackupReader` سند را یک بار تجزیه می‌کند. برای پاکت رمزگذاری‌شده، ابتدا رمزی که کاربر وارد کرده و سپس رمز ذخیره‌شده امتحان می‌شود. خروجی یکی از این سه است:
  - موفقیت؛
  - `PASSWORD_REQUIRED` (رمز پرسیده می‌شود)؛
  - `WRONG_PASSWORD` («رمز نادرست است یا فایل تغییر کرده است»).
- **نسخه‌های ایمنی** پیش از بازیابی، در حافظه خصوصی برنامه و بدون رمز ذخیره می‌شوند (مانند خود پایگاه داده).

### پشتیبان خودکار در پوشه (از نسخه ۱٫۱)
```
انتخاب پوشه (ACTION_OPEN_DOCUMENT_TREE) → takePersistableUriPermission → AppStateStore
FolderBackupWorker (روزانه/هفتگی، باتری و حافظه کافی) → BackupManager.backupToFolder
→ ساخت سند yadino-auto-yyyyMMdd-HHmmss.yadino.json → نوشتن و بررسی بایت‌به‌بایت
→ حذف قدیمی‌ترین پشتیبان‌های خودکار بیش از تعداد انتخاب‌شده (BackupFiles.toDelete)
```
- فقط نام‌هایی که دقیقاً با الگوی پشتیبان خودکار می‌خوانند حذف می‌شوند؛ فایل‌های دیگر پوشه، پشتیبان‌های دستی و نسخه‌هایی که ارائه‌دهنده فایل تغییر نام داده دست نمی‌خورند.
- اگر پوشه حذف یا دسترسی گرفته شود، نتیجه `AccessLost` است. کاربر فقط **یک بار** اعلان می‌گیرد و پس از نخستین پشتیبان موفق، این وضعیت پاک می‌شود.
- آدرس پوشه مخصوص همین دستگاه است و در خروجی تنظیمات یا پشتیبان قرار نمی‌گیرد. فقط تناوب و تعداد نسخه‌ها جزو تنظیمات قابل انتقال هستند.

### جابه‌جایی کارها با کشیدن و رها کردن (از نسخه ۱٫۱)
- `ui.components.DragDrop` (برگرفته از نمونه رسمی AOSP برای `LazyColumn`) با لمس طولانی، کشیدن، پیمایش خودکار در لبه‌ها و پویانمایی جابه‌جایی کار می‌کند.
- ترتیب در حین کشیدن فقط در حافظه تغییر می‌کند و هنگام رها کردن با `TaskRepository.reorder` ذخیره می‌شود.
- `TaskFilters.canReorderTogether` جابه‌جایی را به گروهی محدود می‌کند که مرتب‌سازی برنامه روزانه (`sortForPlan`) اجازه می‌دهد: کارهای هم‌تاریخ که همه باز یا همه انجام‌شده هستند. به این ترتیب آنچه کاربر می‌بیند همان چیزی است که ذخیره می‌شود.
- در حالت جستجو یا فیلتر دسته، جابه‌جایی غیرفعال است، چون ترتیب برای کل برنامه روز تعریف می‌شود.
- دکمه‌های بالا/پایین برای TalkBack و کنترل با کلید باقی مانده‌اند.

### فهرست تیک‌دار در یادداشت‌ها (از نسخه ۱٫۲)
- موارد فهرست به‌صورت خطوط استاندارد فهرست وظیفه (GitHub Flavored Markdown) **درون همان متن یادداشت** ذخیره می‌شوند:
  ```
  خرید هفته
  - [ ] شیر
  - [x] نان
  ```
  بنابراین طرح‌واره پایگاه داده، قالب پشتیبان و همگام‌سازی آینده تغییری نمی‌کنند و نسخه‌های قدیمی‌تر برنامه هم متن خوانا می‌بینند. خواندن، `*` و `[X]` را هم می‌پذیرد؛ نوشتن همیشه `- [ ] ` و `- [x] ` است.
- `Checklist.parse` متن را به بلوک‌های متن و مورد تقسیم می‌کند و `serialize` عکس آن است (برای متنی که خود برنامه نوشته، رفت‌وبرگشت دقیق است).
- `ChecklistEditor` بلوک‌ها را با کلیدهای پایدار نگه می‌دارد تا Compose هنگام افزودن، شکستن، تبدیل یا حذف موارد، فوکوس و نشانگر را از دست ندهد. هر عمل، بلوکی را که باید فوکوس بگیرد (و جای نشانگر) برمی‌گرداند:
  - Enter درون یک مورد، آن را در محل نشانگر می‌شکند. Enter روی مورد خالی، آن را به متن عادی تبدیل می‌کند.
  - چسباندن چند خط، چند مورد می‌سازد (خطوطی که خودشان نشانه‌گذاری فهرست دارند، با همان وضعیت تیک).
  - دکمه فهرست تیک‌دار روی متن، پاراگرافِ زیر نشانگر یا خطوط انتخاب‌شده را تبدیل می‌کند. روی یک مورد، کل رشته موارد پیاپی را به متن برمی‌گرداند و با متن مجاور ادغام می‌کند.
- ViewModel ویرایشگر پس از هر تغییر، `note.content` را از روی بلوک‌ها می‌سازد. بنابراین ذخیره خودکار، پیش‌نویس ضدخرابی و پشتیبان بدون تغییر کار می‌کنند.
- `Note.isBlank` و `NoteFilters.displayTitle` نشانه‌گذاری فهرست را نادیده می‌گیرند. یادداشتی که فقط یک مورد خالی دارد ذخیره نمی‌شود و عنوانِ یادداشت بی‌عنوان هرگز `- [ ]` نیست.
- تبدیل یادداشت به کار: `Checklist.split` موارد غیرخالی را به زیرکار تبدیل می‌کند (موارد تیک‌خورده، انجام‌شده) و فقط پاراگراف‌های متنی در توضیحات کار می‌آیند.
- **جابه‌جایی موارد (از نسخه ۱٫۳)**: `ChecklistEditor.move` یک مورد را با مورد مجاور جابه‌جا می‌کند، فقط درون رشته موارد پیاپی و هرگز به آن سوی یک پاراگراف. کلید بلوک‌ها حفظ می‌شود، پس فوکوس و نشانگر از دست نمی‌رود. بدنه ویرایشگر یک `Column` ساده است (نه فهرست تنبل)، تا فیلدهای متن فوکوس خود را نگه دارند. `ChecklistDragState` ارتفاع ردیف‌ها را نگه می‌دارد و وقتی ردیف کشیده‌شده از نیمه ردیف مجاور بگذرد، جابه‌جایی انجام می‌شود. TalkBack همین کار را با اقدام‌های «انتقال به بالا/پایین» انجام می‌دهد.

### خروجی صفحه‌گسترده CSV (از نسخه ۱٫۲)
- `CsvExporter` از همان نمای لحظه‌ای که پشتیبان استفاده می‌کند (`DataRepository.snapshot`) پنج جدول می‌سازد: `tasks.csv`، `notes.csv`، `goals.csv`، `habits.csv` و `habit_logs.csv`. `SpreadsheetExporter` آن‌ها را در یک فایل ZIP می‌نویسد.
- هر فایل UTF-8 با BOM است (تا اکسل متن فارسی را درست بخواند). جداکننده کاما و پایان خط CRLF است و نقل‌قول طبق RFC 4180 انجام می‌شود.
- تاریخ‌ها در دو ستون شمسی (`1405/07/22`) و میلادی (`2026-10-14`) و زمان‌ها ۲۴ ساعته با منطقه زمانی برنامه نوشته می‌شوند. اعداد لاتین هستند تا صفحه‌گسترده بتواند با آن‌ها محاسبه کند. برچسب‌ها و سرستون‌ها فارسی‌اند.
- متن واردشده کاربر که با `=`، `+`، `-`، `@`، Tab یا CR شروع شود، یک آپاستروف در ابتدا می‌گیرد تا صفحه‌گسترده آن را فرمول اجرا نکند (تزریق CSV).
- موارد فهرست تیک‌دار، زیرکارها و مراحل با ☐/☑ نوشته می‌شوند. پیشرفت اهداف و زنجیره عادت‌ها با همان محاسبه برنامه به دست می‌آید.
- خروجی فقط‌خواندنی است، در وضعیت پشتیبان ثبت نمی‌شود و **رمزگذاری نمی‌شود**. اگر رمزگذاری پشتیبان روشن باشد، پیش از ساخت فایل هشدار داده می‌شود. این فایل قالب بازیابی نیست.

### قالب‌های برنامه (از نسخه ۱٫۳)
```
تقویم ← «ذخیره برنامه روز/هفته به‌عنوان قالب» → TemplateRepository.saveFromPlan → PlanTemplates.fromPlan
صفحه قالب‌ها ← «قالب جدید» / ویرایش → TemplateRepository.save (اعتبارسنجی + یک تراکنش)
«اعمال» → PlanTemplates.preview (پیش‌نمایش و موارد تکراری) → TemplateRepository.apply
      → PlanTemplates.apply در یک تراکنش → DataSideEffects (یادآورها و ابزارک‌ها) → پیام با «واگرد»
```
- **مدل**: `PlanTemplate` (نام، توضیح، بازه ۱ یا ۷ روز) و `TemplateItem`. هر مورد یک روز برنامه‌ریزی (`dayOffset`)، یک مهلت (`dueOffset`) یا هر دو را دارد، درست مانند `Task.date` و `Task.dueDate`. ساعت‌ها مثل کارها «شناور» هستند و زیرکارها فقط عنوان دارند.
- **روزهای قالب هفتگی**: `dayOffset` روز هفته را از **شنبه** می‌شمارد (۰ = شنبه … ۶ = جمعه) و به تنظیم «اولین روز هفته» وابسته نیست. هنگام اعمال، `startFor` آغاز هفته‌ای را که کاربر انتخاب کرده (طبق همان تنظیم) پیدا می‌کند و `position` هر روز را در آن هفته قرار می‌دهد. به این ترتیب مورد «سه‌شنبه» همیشه سه‌شنبه می‌ماند. مهلت موردی که روز برنامه‌ریزی دارد، به‌صورت فاصله از همان روز نگه داشته می‌شود.
- **ساخت از برنامه**: `fromPlan` همان کارهایی را برمی‌دارد که «کپی برنامه» برمی‌دارد: کارهایی که روز مؤثرشان در بازه است، بایگانی و لغوشده نیستند، به ترتیب نمایش و حداکثر به تعداد مجاز. وضعیت انجام و قاعده تکرار عمداً کنار گذاشته می‌شوند.
- **موارد تکراری**: `preview` برای هر مورد روز قرارگیری را حساب می‌کند. اگر در همان روز کاری با همان عنوان باشد (بدون کارهای بایگانی و لغوشده)، مورد «تکراری» علامت می‌خورد. عنوان‌ها با `Validators.comparisonKey` مقایسه می‌شوند: «ي/ك» عربی، ارقام فارسی و عربی، نیم‌فاصله و فاصله‌های اضافه یکسان در نظر گرفته می‌شوند. کاربر می‌تواند موارد تکراری را دوباره نسازد.
- **اعمال اتمیک**: همه کارها و زیرکارها در یک تراکنش ساخته می‌شوند. کارهای تازه پس از ترتیب دستی همان روز قرار می‌گیرند. «واگرد» شناسه کارهای ساخته‌شده را به `TaskRepository.deleteMany` می‌دهد.
- **ذخیره**: `TemplateRepository.save` قالب و فهرست کامل موارد را با هم ذخیره می‌کند. مواردی که در فهرست نیستند حذف می‌شوند و برای همگام‌سازی آینده سنگ‌قبر `TEMPLATE_ITEM` می‌گیرند. مواردی که تغییر نکرده‌اند، زمان تغییرشان را نگه می‌دارند تا ادغام «جدیدتر برنده» در بازیابی درست کار کند. حذف قالب با «واگرد» قابل برگشت است.
- **اعتبارسنجی** (`Validators.template`): نام لازم، با طول مجاز و یکتا (با همان کلید مقایسه). دست‌کم یک مورد و نه بیش از حد مجاز. روزهای موارد درون بازه قالب، و برای هر مورد قواعد عادی کار (ساعت پایان پس از شروع، بازه یادآوری و …).
- قالب‌ها جزو پشتیبان (نسخه ۲) هستند و در «حذف همه اطلاعات» پاک می‌شوند. برنامه هیچ قالب نمونه‌ای از پیش نمی‌سازد.

### خط زمانی نمای روزانه (از نسخه ۱٫۳)
- `DayLayout.layout` (دامنه) کارهای ساعت‌دار را مانند تقویم‌های رایج در ستون‌ها می‌چیند. کارهایی که مستقیم یا از طریق زنجیره‌ای از هم‌پوشانی‌ها هم‌زمان‌اند، یک گروه می‌سازند و عرض را تقسیم می‌کنند. هر کار نخستین ستونی را می‌گیرد که در ساعت شروعش خالی است. دو کار که یکی دقیقاً هنگام شروع دیگری تمام می‌شود، هم‌پوشان نیستند. کار بدون ساعت پایان ۴۵ دقیقه و کار کوتاه دست‌کم ۳۰ دقیقه رسم می‌شود و با همین اندازه در هم‌پوشانی حساب می‌شود.
- **کشیدن**: لمس طولانی و کشیدن، کار را جابه‌جا می‌کند. `DayLayout.move` شروع را به گام ۱۵ دقیقه گرد می‌کند، مدت را نگه می‌دارد و کار را درون همان روز نگه می‌دارد. حرکت کمتر از نیم گام نادیده گرفته می‌شود. دستگیره لبه پایین، ساعت پایان را تغییر می‌دهد (`DayLayout.resize`): گرد به ۱۵ دقیقه، دست‌کم یک گام پس از شروع و حداکثر ۲۳:۵۹.
- **ذخیره**: `CalendarViewModel.retime` کار را با `TaskRepository.save` ذخیره می‌کند. پس اعتبارسنجی، زمان‌بندی دوباره یادآور و به‌روزرسانی ابزارک‌ها مانند ویرایش عادی انجام می‌شود. پیام «واگرد» نسخه قبلی کار را برمی‌گرداند.
- **کارهای تکرارشونده**: نوبت‌های پیش‌بینی‌شده (که در پایگاه داده ذخیره نشده‌اند) کم‌رنگ‌تر و ثابت‌اند. جابه‌جا کردن خود کار ذخیره‌شده، ساعت کل سری را تغییر می‌دهد.
- **دسترس‌پذیری**: هر کار چهار اقدام سفارشی TalkBack دارد (۱۵ دقیقه زودتر، دیرتر، طولانی‌تر و کوتاه‌تر) که همان مسیر ذخیره را طی می‌کنند. لمس هر ردیف ساعت (با برچسب «افزودن در ساعت …») کار تازه‌ای با همان ساعت شروع باز می‌کند.
- خط «اکنون» فقط در روز جاری رسم می‌شود و سر هر دقیقه به‌روز می‌شود. پیمایش اولیه با چگالی واقعی صفحه محاسبه می‌شود.
- `DayTimeline` یک composable جدا از صفحه است و بدون پایگاه داده آزموده می‌شود (`DayTimelineUiTest`).

## مدیریت خطا و حریم خصوصی
- خطاهای پایگاه داده، اعلان و شبکه گرفته و به پیام فارسی تبدیل می‌شوند؛ داده کاربر در خطا دست نمی‌خورد.
- `ErrorReporter` فقط نام کلاس خطا و قاب‌های پشته را ذخیره می‌کند؛ **متن پیام خطا عمداً حذف می‌شود** چون ممکن است حاوی محتوای کاربر باشد.
- **صفحه گزارش خطا (از نسخه ۱٫۳٫۱)**: اگر خطای پیش‌بینی‌نشده‌ای رخ دهد و کاربر برنامه را می‌بیند، `ErrorReporter` به‌جای پیام «برنامه متوقف شد» اندروید، `CrashReportActivity` را باز می‌کند و فرایند خراب را می‌بندد.
  - **چه وقت؟** `AppVisibility` (از روی چرخه عمر Activityها) تصمیم می‌گیرد: صفحه‌ای از برنامه شروع شده باشد، صفحه‌ای همین چند ثانیه پیش ساخته شده باشد (خطا در `onCreate`)، یا خود برنامه هنوز در حال راه‌اندازی باشد. خطای پس‌زمینه (ابزارک، یادآور، WorkManager) فقط ثبت می‌شود و مسیر عادی اندروید را طی می‌کند. اندروید ۱۰ به بالا هم باز شدن Activity از پس‌زمینه را محدود می‌کند.
  - **چرا فرایند جدا؟** صفحه با `android:process=":crash"` اجرا می‌شود. `YadinoApplication` در این فرایند هیچ چیزی راه نمی‌اندازد (پایگاه داده، WorkManager، یادآورها). صفحه هم فقط از Viewهای ساده اندروید استفاده می‌کند، نه Compose. بنابراین خطایی که هنگام راه‌اندازی برنامه رخ داده، این صفحه را از کار نمی‌اندازد.
  - **محتوا**: نسخه برنامه، نسخه اندروید، مدل گوشی و همان پشته بدون پیام `ErrorReporter.sanitize`. دکمه‌ها: کپی، اشتراک‌گذاری (فقط با انتخاب کاربر)، باز کردن دوباره برنامه و بستن. چیزی خودکار ارسال نمی‌شود.
- توکن‌های گوگل و رمز اختیاری پشتیبان با کلید Android Keystore رمز می‌شوند و در SharedPreferences قرار دارند. پشتیبان خودکار اندروید فقط پایگاه داده و فایل‌های DataStore را شامل می‌شود، پس این رازها هرگز از دستگاه خارج نمی‌شوند.
- برنامه جز برای درایو اختیاری، از شبکه استفاده نمی‌کند.

## دسترس‌پذیری و راست‌به‌چپ
- جهت چیدمان در کل رابط RTL است؛ ابزارک‌ها با `layoutDirection="rtl"`.
- توضیح متنی (contentDescription) فارسی برای کنترل‌ها و روزهای تقویم، وضعیت انجام کارها برای صفحه‌خوان.
- پشتیبانی از اندازه متن سیستم به‌علاوه ضریب اندازه متن و مقیاس نمایش برنامه.
- اهداف لمسی حداقل ۴۸dp در کنترل‌های اصلی.
